# Hedwig — Design Context

## Project Summary

Hedwig is a CGM (Continuous Glucose Monitor) data gateway service that collects blood glucose data from Chinese CGM vendors (Ottai, SiSensing) and syncs it to Nightscout. It's a self-hosted, single-jar Spring Boot application with a React frontend built into the same deployable.

## Tech Stack

- **Frontend**: React 18 + TypeScript + Vite
- **UI Library**: Ant Design 5 (antd)
- **State**: Zustand
- **Animations**: Framer Motion
- **Charts**: @ant-design/charts (D3-based)
- **Routing**: React Router v6
- **HTTP**: Axios
- **Date**: Day.js
- **Backend**: Spring Boot 3.2.5 (Java 17+, MyBatis-Plus, PostgreSQL)

## Users

### Primary Audience
- **Diabetes patients** managing their own CGM devices and Nightscout sync
- **Family members / caregivers** remotely monitoring a loved one's glucose data
- Mixed technical backgrounds — some are tech-savvy Nightscout users, others are non-technical caregivers or patients

### Context of Use
- Checking glucose readings quickly (often on mobile)
- Setting up device connections and Nightscout push targets (typically once, on desktop)
- Monitoring connection health and data freshness
- Potentially anxious context — glucose data is health-critical; clarity reduces stress

## Brand Personality

**简洁 · 高效 · 现代** (Clean · Efficient · Modern)

- Efficient and purposeful — every element earns its place
- Modern and polished, but never flashy or decorative for its own sake
- Quietly confident — the interface communicates competence without being cold

### Voice & Tone
- Chinese-language UI throughout (zh-CN locale)
- Concise labels, no jargon
- Warm but professional — clinical precision with human consideration
- Emoji used sparingly (🦉 owl as brand mascot only)

## Aesthetic Direction

### Visual Tone
A blend of **Apple Health's clean minimalism** and **Grafana's dark data-density**:
- Dark mode as the default with full light mode support
- "Clinical Warmth" — the existing design philosophy, balancing medical seriousness with approachable warmth
- Glassmorphism for elevated surfaces (backdrop-blur, subtle borders)
- Gradient accents tied to glucose ranges (teal=normal, amber=low, red=high)

### Typography
- **Body**: DM Sans (Google Fonts) with system fallbacks
- **Monospace**: JetBrains Mono — used for glucose values and numeric data
- Tabular numerals (`font-variant-numeric: tabular-nums`) for aligned number columns

### Spacing & Radius
- Border radius: `8px` (default), `6px` (buttons/inputs), `16px` (auth panels)
- Content max-width: `1200px`, centered
- Content padding: `24px` (desktop), `16px` (mobile)
- Breakpoint: `768px` for mobile/desktop switch

### Motion
- Framer Motion for page transitions and stagger animations
- `0.2s ease` for micro-interactions (hover, focus)
- `0.3s ease` for layout transitions (theme, sidebar)
- Pulse animation for status badges
- Floating dot decoration on auth pages

### Anti-References
- **Nightscout's default UI**: too information-dense, dated visual design
- Overly playful or gamified health apps — glucose data is serious
- Enterprise dashboards with excessive chrome and navigation depth

## Design Principles

1. **Clarity over density** — Glucose data is health-critical. Use visual hierarchy (size, color, spacing) to surface the most important number first. Never obscure readings behind navigation.

2. **Color with meaning** — Every color communicates glucose state (teal=normal, amber=low, red=high) or brand identity (gold). Never use these colors decoratively. Always pair color with a secondary indicator (icon, text, shape) for color-blind users.

3. **Responsive by default** — Users check glucose on phones. Mobile is not an afterthought — the sidebar becomes a drawer, hero cards stack, and touch targets are generous.

4. **Calm confidence** — The interface should reduce anxiety, not add to it. Smooth transitions, consistent patterns, and clear status indicators help users trust that the system is working reliably.

5. **Progressive disclosure** — Simple dashboard first (glucose reading + trend), drill down for history, charts, and configuration. Don't overwhelm on landing.

## Accessibility Requirements

- **WCAG AA compliance** — minimum 4.5:1 contrast for text, 3:1 for large text and UI components
- **Color-blind safe** — glucose range indicators must never rely on color alone; always pair with icons, text labels, or directional shapes (↑↓→)
- **Keyboard navigable** — all interactive elements reachable via Tab, menu items via arrow keys
- **Reduced motion** — respect `prefers-reduced-motion` media query for users with vestibular disorders
- **Screen reader friendly** — use semantic HTML, ARIA labels for icon-only buttons, and meaningful alt text

## Component Patterns

### Existing Patterns to Maintain
- **GlucoseHero**: Large mono-font glucose value with trend arrow, status-colored border
- **VendorCard**: Status border-left (green/amber/red) on Ant Design Card
- **Glass panels**: `backdrop-filter: blur(16px)` with subtle gold-tinted borders
- **Sidebar**: Collapsible Ant Design Sider with owl logo, theme toggle, user info
- **Auth pages**: Split layout — brand panel (left) + glass form (right)

### Key UI Conventions
- Ant Design components used throughout — do not introduce alternative UI libraries
- Inline styles for one-off adjustments, CSS classes for shared patterns
- `zustand` for global state (auth, theme) — keep stores minimal
- Page-level animations via `motion.div` wrapping entire page content
